# A/B 입력과 통합 보조 판정

`python3 start.py --pair` 또는 Windows의 `start-pair-windows.bat`로 실행한다. 기존 검수 화면의 `A/B 통합 판정` 링크로도 같은 화면에 들어간다. Python 3.11 이상이 필요하고, 새 영상을 분석할 때는 기본 프로젝트 의존성과 FFmpeg/ffprobe가 필요하다.

## 사용 흐름

1. A와 B에 같은 착지 사건을 촬영한 영상을 각각 지정한다. 기존 영상 목록에서 선택하거나 파일 두 개를 업로드한다.
2. 사용자가 같은 랠리임을 확인한 경우 해당 항목을 표시한다. 기존 검수에서 실제 동작 대응이 확인된 쌍은 그 근거로 연결할 수 있다. 파일 번호가 같다는 이유만으로 사건을 확정하지 않는다.
3. 기본값은 원본을 새로 분석하는 방식이다. `기존 검수 근거 활용`을 직접 켜면 원본 SHA256이 일치하는 저장 결과를 활용한다. 새 영상에 기존 파일 이름만 붙여도 레이블이 재사용되지 않는다.
4. `A/B 연결 분석`을 누르면 A·B의 진행 상태와 하나의 최종 보조 판정이 나타난다. 각 시점의 자동 판정, 직접 검수 결과, 판정 출처와 근거 영상을 함께 확인한다.
5. 결과 URL을 보관하면 새로고침하거나 서버를 다시 실행한 뒤에도 저장된 작업을 확인할 수 있다.
6. REVIEW의 진단 패널에서 시점별 부족 근거와 후속 조치를 확인한다. 검수 구간이 있으면 해당 시각으로 이동한다. 원본과 검증된 후보 위치가 있을 때 `접촉 후보 구간 집중 재분석`을 실행하면 기존 AI 검수 구간을 참고한 새 분석을 수행한다. 기존 판정을 복사하지 않으며, 적용된 시점과 보조 분석 출처를 표시한다.

입력은 영상별 1GiB, 현재 분석 설정의 최대 3,000프레임으로 제한한다. 제한을 넘는 영상을 조용히 잘라서 판정하지 않는다. 새 영상은 한 작업 안에서 최대 두 개를 병렬 분석하며, 작업별 상태와 실패 사유를 보존한다.

## 분석 진행 확인 (0.5.1)

분석을 시작하면 업로드·대기·A/B 분석·결과 연결의 흐름을 진행 화면에서 확인할 수 있다. 업로드는 실제 전송한 크기를 표시하며, 전송이 끝난 뒤 서버가 영상 파일을 확인하는 과정도 구분한다.

새 분석은 A와 B 각각의 현재 단계와 완료한 단계를 표시한다. 단계는 영상 준비, 코트 확인, 셔틀콕 후보 탐지, 궤적 연결, 착지·라인 확인, 근거 영상 생성, 결과 저장 순서다. 프레임 처리량을 제공하는 단계에서는 처리한 프레임 수와 전체 프레임 수도 확인할 수 있다. 기존 검수 재사용은 새 영상 분석과 구분한다.

0.5.2부터 착지 추정의 시간·프레임 구간과 영상 속 근사 위치, 원본 전후 확대 및 선택 경로 재생 영상을 제공한다. 접촉 미확인 후보는 관측된 접촉과 분리하며, 가림·누락 구간의 추정을 관측점으로 채우지 않는다. [실제 영상의 수정 전후](SHUTTLE_TRACKING_FIX.md)에 검증 범위를 기록했다.

경과 시간은 실제 작업 시작 시점을 기준으로 표시하며 대기 시간과 구분한다. 각 단계의 소요 시간은 해당 단계에서 실제로 측정한 값이다. 단계마다 필요한 계산량이 다르므로 완료한 단계 비율을 남은 시간의 예측값으로 해석하지 않는다.

작업 URL을 다시 열거나 새로고침하면 저장된 진행 상태를 복원한다. 연결이 끊긴 경우에는 마지막 확인 상태와 재시도 방법을 표시한다. 실패·중단된 작업은 멈춘 단계를 남기고 완료로 표시하지 않는다. 프로그램 종료 후 복원된 중단 작업의 경과 시간은 종료 이후 계속 늘어나지 않는다. 이전 버전에서 생성한 작업에 단계 기록이 없으면 확인 가능한 상태와 시간만 표시한다.

## 최종 결과의 의미

| A/B 근거 | 최종 결과 |
|---|---|
| 같은 사건임이 확인되고 한 시점에서 충분한 IN/OUT 근거가 있으며 다른 시점은 접촉을 관측하지 못함 | 근거가 있는 시점의 판정을 사용하고 해당 시점을 표시 |
| 양쪽에서 충분한 직접 판정 근거가 있고 결과가 일치 | 일치한 결과 |
| 양쪽 직접 판정이 충돌 | REVIEW |
| 같은 사건 확인이 부족하거나 기존 검수에서 다른 랠리로 확인됨 | REVIEW |
| 동일 파일을 A/B에 중복 입력 | REVIEW |
| 양쪽 모두 미해결이거나 분석 실패 | REVIEW와 사유 |

이 연결은 판정 근거의 연결이다. 카메라 좌표를 같은 좌표계로 변환하거나 3D 위치를 복원하지 않는다. 원본 접촉 좌표와 시각은 관측한 시점에 속한다. 두 영상의 프레임 번호가 같다고 같은 순간으로 취급하지 않는다.

AI 검수 근거를 사용한 결과와 사용자의 사건 대응 확인을 사용한 결과는 보조 판정으로 표시하며, 독립된 사람 정답이나 무보조 자동 모델 정확도로 집계하지 않는다. 새 자동 분석의 탐지·접촉 근거가 부족하면 A/B를 함께 입력해도 REVIEW가 나올 수 있다.

## 저장과 API

기본 실행은 `runs/pair-workspace/paired/` 아래에 새 업로드와 작업을 저장한다. 기존 자동 분석과 74개 AI 검수 기록을 덮어쓰지 않는다. `--run`으로 실행 폴더를 바꾸면 해당 폴더의 `paired/`를 사용한다. 종료 중이던 작업은 재실행 시 완료로 위장하지 않고 중단 상태로 표시한다.

- `GET /api/pair-library`: 선택할 수 있는 기존 영상과 입력 제한
- `POST /api/pair-uploads`: 단일 영상 바이트 업로드. `Content-Type: application/octet-stream`, `Content-Length`, URL 인코딩한 `X-Filename` 사용
- `POST /api/pair-jobs`: A/B 입력과 사건 대응 확인, 저장 검수 활용 여부를 제출
- `GET /api/pair-jobs`: 작업 목록
- `GET /api/pair-jobs/{job_id}`: 진행 상태와 최종 결과 JSON

입력 예시:

```json
{
  "views": {
    "A": {"video_id": "v_3c33c9503c95"},
    "B": {"video_id": "v_76a246813dcb"}
  },
  "same_event_confirmed": false,
  "reuse_review": true
}
```

업로드 파일을 사용할 때는 `video_id` 대신 업로드 응답의 `upload_id`를 지정한다. 이 예시의 A5/B5는 저장된 실제 동작 대응 근거가 있는 쌍이며, 새 임의 입력에는 같은 결론을 가정하지 않는다.

## 0.5.0 재검수·집중 재분석

기존 양쪽 REVIEW 15쌍의 원본을 재검수해 일반 8번과 UHD/HD 3번의 최초 접촉을 복구했다. 이 두 쌍은 IN으로 연결하고 13쌍은 구체적인 사유와 함께 REVIEW로 유지한다. 추가로 8K/4K 6번의 연결 누락을 해결했다. 최종 37쌍 결과는 **IN 18 / OUT 5 / REVIEW 14**다. [15쌍 전체 원인·개선 보고서](REVIEW_REMEDIATION.md)를 참조한다.

집중 재분석 API는 `reuse_review: false`, `refine_review_regions: true`를 함께 사용한다. 원본 SHA256이 일치하는 검수의 실제 관측 프레임·후보 위치를 검색 힌트로 사용하며, `review_guided_reanalysis` 및 적용 시점 목록을 결과에 기록한다. 검수 힌트가 없는 시점은 일반 새 분석을 수행한다. 원본 없는 열람용 패키지에서는 원본을 업로드해야 집중 재분석을 실행할 수 있다.

## 0.4.0 도입 당시 검증 기록

- 전체 소프트웨어 테스트 370개 통과. A/B 판정 연결, 업로드, 원본 해시, 작업 복원과 HTTP 경계 조건을 포함한다.
- 실제 브라우저에서 A5/B5 선택·파일 업로드, A/B 위치 교환, 양쪽 미해결, 중복 입력, 다른 랠리 입력, 접촉 시각 이동, 새로고침 복원과 모바일 화면을 확인했다.
- 프로젝트의 74개 영상으로 구성한 37개 후보 쌍을 실제 API로 처리했다. 사용자의 추가 사건 대응 확인 없이 저장된 검수만 활용한 결과는 **IN 15쌍 / OUT 5쌍 / REVIEW 17쌍**이다. 이는 쌍별 통합 결과이며, 기존 74개 개별 영상의 집계와 기준이 다르다.
- 원본 A5/B5 두 파일을 업로드하고 검수 재사용을 끈 새 분석도 실행했다. 두 시점을 병렬 처리하여 작업 전체 **100.67초**가 걸렸고, 양쪽 자동 판정과 최종 결과는 **REVIEW**였다. 기존 검수 연결을 사용하면 같은 입력의 최종 결과는 **IN**이다. 저장 검수의 결합 속도를 새 영상의 추론 속도로 해석하면 안 된다.

검증 기록과 화면 캡처는 `runs/pair-validation/`에 보관한다. 위 시간은 이번 CPU 실행의 측정값이며 GPU 또는 다른 길이·해상도 영상의 처리 시간을 보장하지 않는다. 이번 변경은 A/B 입력과 결과 연결 기능을 추가했으며, 자동 탐지 모델의 정확도 향상을 검증한 것은 아니다.
