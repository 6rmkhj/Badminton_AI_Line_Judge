# Windows 근거 파일 저장 오류 수정 · 0.5.13

0.5.12에서 A/B 모두 착지·라인 확인을 끝낸 뒤 `근거 영상 생성` 단계에서 `OSError`로 중단되는 문제가 보고되었습니다. Windows OpenCV의 파일명 기반 `imwrite`가 한글 경로를 처리하지 못하면 첫 코트 근거 이미지 저장에서 이 오류가 발생합니다. 원본 착지 몽타주나 추정 표시 이미지 저장 실패도 앞서 계산한 영상 추정을 보류로 바꾸고 있었습니다.

## 변경

- 이미지 코덱에는 바이트만 전달하고 Python 파일 입출력으로 경로를 처리합니다. 사진, 원본 확대 몽타주, 검수 이미지, 근거 영상의 임시 JPEG에 동일하게 적용합니다. 임시 파일을 닫은 뒤 원자적으로 교체합니다.
- 계산과 선택적 근거 파일 생성을 분리합니다. 파일 저장·인코딩 실패는 `evidence_warnings`로 표시하고 결과 JSON, 관측, 코트, 계산된 판정은 보존합니다. 실패한 파일 링크는 결과에 등록하지 않습니다. 원본 분석 자체가 실패하면 완료된 판정으로 표시하지 않습니다.
- 결과 JSON과 FFmpeg 텍스트 입출력에 UTF-8을 명시합니다. 실제 분석 실패에는 단계·오류 메시지·OS 오류 번호를 표시하고 작업 폴더에 traceback을 저장합니다.
- 판정 기준, 위치 오차, 단식·복식 경계, 직접 접촉 확인 조건은 변경하지 않습니다. 영상 추정과 직접 확인 판정의 구분을 유지합니다.

## 회귀 검증과 배포 조건

자동 테스트는 한글 출력·임시 경로의 이미지 왕복 저장, 실제 FFmpeg 근거 영상과 원본 프레임 시각 정합, 사진 쓰기 권한 오류·인코더 실패에도 IN/OUT 계산 보존, UTF-8 결과 저장, 경고 화면과 새로고침을 확인합니다. 실패를 주입한 IN/OUT 테스트는 결과 보존 검증이며 탐지 정확도 측정이 아닙니다.

이전 Windows 검증은 실행기와 계산 단위 테스트를 검사했으며 실제 영상의 근거 생성 단계까지 실행하지 않았습니다. 0.5.13 배포에는 `scripts/verify_windows_analysis.py`를 추가해 패키지에 포함된 Python·OpenCV·FFmpeg로 다음을 검사합니다.

1. 한글 경로에서 기존 OpenCV 저장 결과와 새 이미지 입출력의 무손실 왕복을 기록합니다.
2. 고정 커밋의 원본 영상을 다운로드하고 크기와 SHA-256을 검증합니다.
3. 한글·공백이 있는 입력, 출력, 임시 폴더에서 A 복식, B 복식, A 단식의 기본 분석을 처음부터 실행합니다.
4. 모든 단계 완료, 결과 JSON 저장, 근거 사진·동영상 디코딩, 영상 프레임·시간 정보, 근거 생성 경고 없음과 기존 예상 결과를 확인합니다.
5. START의 PowerShell 5.1 압축 해제·재실행·HTTP 검사와 위 분석이 모두 통과해야 릴리스를 공개합니다. 실제 실행 기록은 릴리스의 `windows-0.5.13-validation.json`에 첨부합니다.

A 영상은 저장소의 같은 파일명 원본이며 대용량 사용자 첨부본과 바이트 일치는 검증하지 못했습니다. B 원본은 첨부 영상과 SHA-256이 같습니다. 기존 회귀 결과는 A 복식 IN·단식 OUT(영상 추정), B REVIEW입니다. 이 검사는 실행·저장 오류 회귀를 확인하며 독립적인 실제 접촉 정답이나 사용자 PC 전체 환경의 정확도를 보증하지 않습니다.

## 적용

0.5.13 전체 ZIP을 새 폴더에 모두 압축 해제하고 `START.bat`으로 실행합니다. 이전 실패 작업을 열기만 해서는 결과가 복구되지 않으므로 영상을 선택해 새 분석을 실행하세요. 근거 파일 경고가 남으면 화면에 나온 파일·오류 메시지를 확인할 수 있습니다.
