# 통합 PoC 검증

이 검증은 프로젝트 영상 전체를 대상으로 입력부터 판정 사유·원본 근거 생성까지의 실행을 확인한다. 관측되지 않은 최초 접촉이나 검수되지 않은 셔틀콕 후보를 정답으로 만들지 않는다. 소프트웨어 실행 통과와 실전 자동 판정 정확도 입증은 별개다.

## 재현 절차

Python 환경 설치 후 저장소 루트에서 실행한다. `input-manifest-before.json`은 분석 **전**에 저장하여 분석 후 원본이 그대로인지 비교한다.

```bash
python -c "import json; from pathlib import Path; from badminton.dataset import build_manifest; p=Path('runs/inspection/input-manifest-before.json'); p.parent.mkdir(parents=True, exist_ok=True); p.write_text(json.dumps(build_manifest('video'), ensure_ascii=False, indent=2), encoding='utf-8')"
python -m badminton analyze video --config configs/poc.json --output runs/integrated-poc
python -m badminton evaluate --run runs/integrated-poc
python -m badminton.reporting --run runs/integrated-poc
python scripts/validate_integrated_poc.py \
  --run runs/integrated-poc --video-dir video \
  --input-snapshot runs/inspection/input-manifest-before.json
```

기본 감사는 원본의 표시 시각을 `ffprobe`로 새로 읽고, 모든 미리보기 프레임을 별도로 디코딩한다. `--decode-source`를 추가하면 원본 영상도 전부 독립 재디코딩한다. 분석 자체에서 이미 원본·미리보기 프레임을 읽었더라도 감사 결과는 이 독립 반복 여부를 별도 기록한다.

판정 요청 실행 결과도 검사하려면 `--request-result runs/요청실행/request-result.json`을 추가한다. 이 옵션은 여러 번 지정할 수 있다. 사람이 지정한 사건·타격 앵커를 사용한 요청 결과를 무보조 자동 모델 성과나 정답으로 계산하지 않는다.

## 감사 항목

| 항목 | 확인 내용 |
|---|---|
| 전체 입력 | 현재 `video/`의 MP4 목록, 실행 목록, 매니페스트의 일치 |
| 원본 보존 | 분석 전·후 실제 SHA256, 매니페스트, 영상별 결과의 원본 해시 일치 |
| 시간과 프레임 | 원본 표시 시각, 미리보기 표시 시각·실제 디코딩 수, 결과·탐지 프레임 수와 시각 일치 |
| 재현성 | 모든 영상의 구현 지문이 현재 분석 코드와 일치하는지 확인 |
| 원본 분석 | 고해상도 탐지 실행 여부, 원본 ROI 경계, 접촉 후보 원본 시퀀스의 프레임·시각·영역 |
| 근거 출력 | 결과가 참조하는 이미지·영상·JSON 존재, 이미지 디코딩, 근거 영상의 표시 프레임 |
| 판정 | 보정이나 카메라 안정성이 수락되지 않은 상태에서 자동 IN/OUT을 내리지 않는지 확인 |
| 학습·정답 출처 | 접촉 관측을 선언한 모델의 자격 정보, 검수 정답 부재 시 정확도 `null` 유지 |
| 판정 요청 | 담당 카메라 결과·원본 일치, 요청 시간 범위, 동일 사건·공통 코트 좌표계 확인 및 수동 보조 표기 |

감사 실패는 종료 코드 1과 `integrated-validation.json`의 `errors`·영상별 `errors`로 확인한다. `software_integrity_passed=true`는 위 실행·무결성 검사 통과이며, 코트 보정이나 셔틀콕 인식의 정답 대비 성공률을 뜻하지 않는다.

`b시점 17.mp4`와 `b시점 18.mp4`는 내용이 같은 중복이다. 중복과 파일명상 연결된 랠리를 묶으면 36개 그룹이며, train 26 / val 5 / test 5개 그룹으로 나뉜다. 이는 체육관·날짜·기기의 독립성을 입증하지 않는다.

MP4 메타데이터의 `nb_frames`를 실제 표시 프레임 수와 동일하게 취급하지 않는다. 113개 discard/preroll 패킷이 있고, `b-3시점(uhd30 4k30).mp4`에는 편집 목록으로 제외된 15개 패킷이 따로 있다. `8k 30 4k 24 b시점 1.mp4`에는 중앙 프레임 간격의 1.5배를 넘는 표시 시각 간격이 관측됐다. A/B를 같은 프레임 번호로 동기화하지 않는다.

대표 프레임을 직접 확인했을 때 청색 코트 선, 광각 원근, 일부 잘린 코트, 인접 코트와 선수·네트 가림이 보인다. 부분 시야에서 전체 코트 좌표를 유일하게 정할 수 없으면 보정은 REVIEW로 남아야 한다.

모든 결과가 같은 분석 코드 지문(`ad7a12b7fe29b3ea633b64caa1f94f23d6d6539b7ebc9005f0b771633b6e0d31`)을 가진다. 감사에서는 미리보기 전체를 별도로 디코딩하고 원본의 표시 시각과 대조했다. 원본 전체의 디코딩은 분석의 고해상도 경로에서 수행했으며, 감사에서 다시 반복하지는 않았다. 판정 요청 예제도 실제 A/B 영상 두 개로 실행·감사했고, 동일 사건·공통 코트 방향이 확인되지 않은 상태에서 REVIEW를 유지했다.

코트 보정 보류 사유는 부분 라인만으로 코트 평면을 유일하게 정할 수 없음 36개, 코트 템플릿 지지 부족 38개, 부분 시야 22개, 복수 정합 가설 모호성 17개, 카메라 안정성 확인 불가 3개다. 한 영상에 여러 사유가 있을 수 있다. 이러한 보류를 수락으로 바꾸어 성공률을 만들지 않았다.

셔틀콕·접촉 학습 가중치를 사용한 영상은 0개이며, 원본 시퀀스는 접촉 **후보의 근거**이지 접촉 확인이나 정답이 아니다. 후보 예산에 도달한 프레임은 13,958개이고, 93,665개 궤적 중 93,047개에 식별 모호성이 기록됐다. 이 수치는 진단 자료로만 보고하며 탐지 재현율, ID 정확도, TrackNetV3 대비 개선이나 실제 오판율로 해석하지 않는다. A/B 후보 37쌍의 자동 오디오 동기화도 모두 보류됐다.

실행 환경은 Python 3.12.14, CPU 4개분 할당, 메모리 제한 16GiB다. 분석·평가·보고서 생성까지 벽시계 약 **48분 22초**가 걸렸으며, 병렬 처리한 개별 영상 분석 시간을 합하면 약 5,481초다. 최종 독립 감사 시간은 이 벽시계 수치에 포함하지 않는다. 현재 구현은 비실시간 연구용이다.

전체 소프트웨어 테스트 257개가 통과했고, 감사 스크립트의 회귀 테스트 13개도 통과했다. 두 테스트 집합은 겹치므로 개수를 합산하지 않는다. Chromium에서 최종 74개 목록, 프레임 이동, 원본 시퀀스와 주석 영상 재생, 마지막 영상의 87번째 프레임 접근을 확인했다. 데스크톱·모바일 가로 넘침과 페이지 오류가 없었고, 로컬 실행기의 HTTP 200 및 최종 74개 결과 연결도 확인했다.

버전 관리되는 최종 수치는 [integrated-poc-results.json](integrated-poc-results.json)에 있다. 전체 감사는 `runs/integrated-poc/integrated-validation.json`, 실행·브라우저·테스트 근거는 같은 폴더의 JSON·로그·스크린샷에 보존한다. 사람이 검수한 독립 정답이 없으므로 실제 판정 정확도와 95% 신뢰구간은 `null`이며, 실전 성능 입증 완료를 뜻하지 않는다.
