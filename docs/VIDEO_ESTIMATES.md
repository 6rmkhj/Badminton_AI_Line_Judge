# 원본 영상 기반 착지 범위와 IN·OUT 추정 — 0.5.12

## 문제와 구현 계획

기본 OpenCV 분석은 움직임 후보를 생성하지만 `contact_observed=false`를 유지하고, 대상 식별 점수도 기존 직접 접촉 판정 기준에 미치지 않도록 설계되어 있었다. 원본 확대 이미지를 저장해도 이를 해석하는 별도 경로가 없었다. 같은 착지에서 갈라진 궤적 여러 개와 다른 코트 후보까지 사건 목록에 남아, 후보를 더 잘 찾는 것만으로 최종 판정이 가능해지지 않았다.

다음 순서로 구현했다.

1. **사건 연결:** 주 코트에서 실제로 관측된 경로를 확인한다. 충분한 실측 접근 경로를 공유하며 시간·위치 범위가 겹치는 후보만 한 사건의 대안으로 묶는다. 다른 코트 움직임과 관측된 연속 하강에 모순되는 공백 반전은 사유를 남겨 제외한다. 독립적인 두 착지가 남으면 하나를 임의로 선택하지 않는다.
2. **원본 근거 계산:** 원본 크기에 맞춰 탐색 영역을 확장하고 착지 전후의 실제 픽셀 변화를 측정한다. 고정 배경과 움직이는 성분을 분리하고, 접근·반등 경로와 원본 물체 영역이 이어지는지 확인한다. 작은 기존 패치에 잘려 사라지던 블러·깃털·코르크 주변을 함께 보존한다. 프레임 사이의 위치·시간 오차를 포함해 가능한 접촉 영역을 계산한다.
3. **전체 영역 판정:** 가능한 모든 위치와 경계 오차를 비교한다. 전체가 확인된 코트 내부이면 영상 추정 IN, 전체가 관측된 같은 외곽선 밖이면 영상 추정 OUT이다. 일부만 안쪽이거나 선에 걸치는 범위, 관측 선의 연장선에서만 OUT인 범위는 REVIEW다. 단식·복식은 선택한 실제 경계에 맞춰 같은 함수를 사용한다.
4. **화면과 출처:** 결과에 영상 추정임을 명시하고 원본 확대 근거·시간 구간·가능한 영역·경계 여유를 함께 보여준다. 한 시점에서만 유효한 영상 추정이 나오면 그 시점의 결과와 출처를 사용한다. 서로 모순되는 유효한 결과를 숨기지 않는다.
5. **고정 대조 검증:** 제공된 A/B와 추가 원본 4개, 정지·공중 비행만 있는 구간·접촉 구간 누락·물체 가림·카메라 이동 대조를 확인한다. 원본 해시와 검증 명세를 먼저 고정하고, 결과를 본 후 정답이나 기준을 바꾸지 않는다.

## 판정의 의미

영상 추정은 저프레임 영상에서 코르크의 최초 접촉 순간을 직접 확인한 결과와 구분한다. 선택한 원본 성분이 대상 셔틀이고, 첫 영상상 반전이 바닥 반등이며, 접촉 부근이 측정한 국소 운동 모형을 따른다는 가정이 있다. 표시하는 오차는 원본 성분 범위·모형 잔차·카메라 변위·픽셀 양자화로 계산한 조건부 범위이며, 통계적으로 검증된 신뢰 구간이나 판정 정확도가 아니다. 기존 `decision`, 접촉 관측 여부와 식별 점수는 그대로 보존하며, 새 `video_estimate`에 원본 측정·사건 연결·가능 영역·판정 이유를 기록한다. 표시 결과는 `display_decision`, A/B 통합 결과는 `decision_kind: video_estimate`로 출처를 명시한다. 직접 접촉 판정이 있으면 그 결과를 우선한다.

추정 경로는 직접 관측으로 승격하지 않고, 검증된 모델의 확률이나 독립 정답 정확도로 집계하지 않는다. 완전히 가려진 접촉, 보이지 않는 코트 범위, 여러 물체가 구분되지 않는 경우에는 가능한 범위를 만들어 채우지 않는다. 추정이 확정되지 않으면 REVIEW를 유지한다.

이 기능은 새 분석에 기본 적용한다. `"video_estimate": {"enabled": false}`로 끌 수 있다. 기존 저장 결과를 열기만 하면 새 원본 계산은 수행하지 않으므로, A/B 화면에서 기존 검수 활용을 끄고 새 분석을 실행한다. 정밀 판정 범위는 현재 단식·복식 랠리이며 서비스 선택은 이 A/B 경로에 포함되지 않는다.

## 검증 자료와 해석

실제 A는 첨부 전송 한도로 저장소의 동명 원본을 사용한다. 현재 첨부와 바이트 동일성은 확인하지 못했다. B는 사용자 첨부 원본이다. 추가 4개 원본은 같은 체육관의 기존 개발 자료로, 독립적인 새 환경의 홀드아웃 정확도로 주장하지 않는다. 영상 추정과 엄격한 직접 접촉 판정을 별도 집계하며, 구현 단위 시험·실제 영상 실행·화면 모의 응답 시험을 구분한다.

### 구현 중 발견해 수정한 회귀

- 원본과 분석 영상의 가로·세로 축척이 다를 때 평균 축척을 좌표 변환에 사용하면 경계에 걸친 범위가 잘못 IN이 될 수 있었다. 각 축의 비율로 좌표·탐색 영역·면적·원본 표시를 변환하며, 같은 경계의 비등방 리사이즈가 REVIEW를 유지하는 회귀 시험을 추가했다.
- 첫 전체 A/B 실행은 A의 서로 다른 시점에 생긴 블러 조각과 바닥 음영을 두 번째 셔틀로 합산해 두 경기 방식 모두 REVIEW였다. 실제 두 번째 경로를 판단할 때 연속 시간·공간 연결을 요구하도록 수정했다. 작은 별도 물체의 연속 관측은 계속 REVIEW다. 첫 실패 결과와 수정 후 결과는 별도 실행으로 보존한다.

영상 추정의 지원 범위는 일반화된 정확도가 아니다. 아래 실행 기록은 이 구현으로 실제 어떤 결과가 나왔는지와 근거 없는 입력을 보류하는지 확인한다.

### 최종 실행 결과

같은 소스 지문 `7082b731c31440d495dc81750a17e78f82ded1d3f626c4eca6f8d01b224da1e8`으로 새 분석을 실행했다. A/B는 실제 `PairWorkspace` 업로드와 작업 실행 경로를 사용했고, 단식·복식을 각각 처음부터 분석했다.

| 입력 | 경기 방식 | 직접 접촉 기반 결과 | 영상 추정 / 최종 표시 |
| --- | --- | --- | --- |
| A 동명 저장소 원본 | 복식 | REVIEW | **IN** |
| A 동명 저장소 원본 | 단식 | REVIEW | **OUT** |
| B 사용자 첨부 | 복식·단식 | REVIEW | REVIEW |
| A/B 통합 | 복식 | 양쪽 REVIEW | **A 근거로 IN** |
| A/B 통합 | 단식 | 양쪽 REVIEW | **A 근거로 OUT** |
| 추가 기존 원본 4개 | 복식 | REVIEW 4개 | REVIEW 4개 |
| 정지·카메라 이동·공중 비행·접촉 구간 누락·접촉 영역 가림 | 복식 | REVIEW 5개 | REVIEW 5개 |

A에서 실제 원본 프레임 19개를 읽어 연속 성분 10개와 같은 착지의 대안 후보 6개를 확인했다. 가능한 범위는 분석 영상 960×540 기준 x345.0–376.5, y431.625–455.375이며 추가 오차는 3.716픽셀이다. 프레임 48–51, 1.600–1.700초 구간을 사용했다. 코트 라인 오차까지 포함한 최소 여유는 복식 내부 10.385픽셀, 단식 왼쪽 외부 17.475픽셀이다. 물리 접촉이나 대상 식별을 직접 확인했다는 플래그는 변경하지 않았다.

추가 4개는 동일 소스의 0.5.11 실행과 엄격 판정 결과가 동일했다. 대조 5개는 사건 연결 단계에서 REVIEW였으므로 원본 추정기의 오탐률을 측정한 것은 아니다. 별도로 원래 A의 추적·보정 근거를 주입하고 원본 픽셀만 가림·정지 영상으로 바꾸는 격리 시험을 수행했다. 두 경우 모두 원본 모듈이 REVIEW였고 접촉 영역을 생성하지 않았다. 이 시험은 생산 추론이나 독립 정답 정확도 평가와 구분한다.

전체 Python 테스트 **1,316 통과·12 건너뜀**. 실제 결과를 제공하는 서버의 브라우저 검사에서 두 경기 방식의 최종 판정·출처·원본 사진·시간 이동·기록·새로고침과 375/390/1440픽셀 화면을 확인했으며 JavaScript 및 근거 사진 요청 오류는 0개였다. 실제 영상 검증과 별개로 화면 모의 응답 시험도 수행했다. Windows의 시작·번들 런타임 검증 결과는 릴리스의 `windows-0.5.12-validation.json`에 별도로 제공한다.
