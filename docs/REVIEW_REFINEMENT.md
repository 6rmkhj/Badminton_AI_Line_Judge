# REVIEW 구간 집중 재분석

이 기능은 검수에서 발견한 작은 셔틀 후보를 원본 픽셀에서 다시 찾는다. 최초 접촉·대상 셔틀·코트 경계의 확인을 대신하지 않으며, 입력한 검수 구간 때문에 `assistance_used=true`로 기록한다. 기본 자동 분석 설정은 변경하지 않았다.

## 개선한 부분

- 전역 후보의 밝기 순서만으로 원본 탐색 창을 배정하면 선수 옷·선·배경에 예산을 소모한다. 검수 구간에서는 기존 원본 탐색 창 8개 중 최대 4개를 해당 영역에 우선 배정한다. 나머지 전역 후보·탐색 창도 유지한다.
- 최종 후보 64개 중 최대 16개를 지정 영역의 실제 관측 후보에 우선 배정한다. 좌표를 입력값에서 복사하거나 후보 점수를 올리지 않는다.
- 밝은 바닥과 어두운 코르크가 하나의 큰 영역으로 합쳐져 크기 필터에 제거되던 문제를 집중 재분석에서 수정했다. 원본의 국소 명암 구조를 먼저 분리하고 기존 움직임·배경 차이 조건으로 확인한다.
- 중복 후보 제거는 공간 버킷을 사용해 큰 후보 풀의 비용을 줄인다. 기존 순위·가변 반경 억제 결과와 동일한지 회귀 테스트로 확인한다.

`candidate_selection="spatial"`은 영상 격자별 후보를 차례로 남기는 선택 기능이다. 어려운 영상에 명시적으로 설정할 수 있으나 기본값은 기존 점수 순서인 `ranked`다.

## 설정 계약

아래 예시의 좌표와 프레임 범위는 분석할 영상에 맞게 지정한다. `bbox`는 분석 해상도의 `[x, y, width, height]`, 프레임 번호는 원본 디코딩 순서의 0부터 시작하는 인덱스이며 양 끝을 포함한다. 최대 16개 영역을 지원하고 화면·시간 범위를 벗어나면 오류로 거부한다.

```json
{
  "analysis_width": 960,
  "detector": {
    "include_dark_components": true,
    "refinement_regions": [
      {"frame_start": 80, "frame_end": 95, "bbox": [250, 330, 80, 70]}
    ]
  }
}
```

`python -m badminton analyze 원본.mp4 --config 설정.json --output runs/refined`로 실행한다. 재분석은 압축 미리보기를 확대하지 않고 원본에서 분석 프레임과 원본 탐색 창을 읽는다.

`detections.json`의 프레임별 `refinement`에는 활성 영역, 우선 보존 후보 수, 보조 입력 사용 여부가 기록된다. 원본 후보의 `roi_origin="review_refinement_region"`은 탐색 위치의 출처이며 접촉이 검증됐다는 뜻이 아니다. `provides_contact_evidence`와 `provides_target_identity`는 false로 유지한다.

## 실제 영상 검증의 범위

`python scripts/benchmark_review_candidates.py`는 기존 양쪽 REVIEW 쌍에서 AI가 셔틀 위치를 표시한 영상을 골라 같은 원본 연속 구간·후보 예산으로 비교한다. 기본 탐지, 어두운 후보 추가, 집중 재분석, 공간 분산 선택을 구분한다. 탐색 영역을 기존 검수 위치에서 만들므로 결과는 **검수 보조 후보 보존 능력**에 대한 개발 실험이다. 독립 영상의 탐지 재현율·IN/OUT 정확도가 아니다. 시간도 해당 구간의 탐지 단계만 측정하며 원본 디코딩이나 전체 분석 시간으로 사용하지 않는다.

이번 비교는 개선 전 양쪽 REVIEW 15쌍 중 AI 셔틀 위치가 있던 7개 영상의 28개 위치, 원본 연속 163프레임으로 실행했다. 6px 이내 후보가 남은 위치는 기본 탐지 **5/28**, 어두운 후보만 추가 **3/28**, 집중 재분석 **23/28**, 집중 재분석과 공간 분산 선택 **23/28**이었다. 어두운 후보만 켜면 악화될 수 있어 기본 설정으로 승격하지 않았다. 공간 분산 선택도 이 실험에서 추가 이득이 없어 기본으로 사용하지 않는다.

결과는 `runs/review-remediation/pipeline/candidate-benchmark.json`, 원래 검수 입력과의 위치·해시 일치 확인은 `benchmark-input-equivalence.json`에 있다. 초기 대상 집합을 다시 비교하려면 `--report runs/review-remediation/baseline/visual-review.json`을 지정한다.

가림, 화면 밖 접촉, 클립 조기 종료와 경계 픽셀의 불확실성은 원본 탐색을 추가해도 해결되지 않을 수 있다. 그 경우 REVIEW 사유를 유지한다.
