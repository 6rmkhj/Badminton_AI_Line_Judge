# 원본 해상도 착지 접촉 분석

통합 파이프라인은 착지 후보마다 원본 영상의 전후 2프레임, 총 5프레임에서 고정 위치 패치를 추출합니다. 프레임 번호와 표시 시각은 원본 디코딩 순서와 일치하며, 축소된 검수용 영상을 다시 확대하지 않습니다. 한 번의 순차 디코딩으로 필요한 패치만 보관합니다.

`landings[].source_contact_evidence`에는 원본·분석 크기, 좌표 배율, 원본 후보점, 각 패치의 실제 원본 영역, 시각, 화면 밖 패딩 비율, 명암 대비와 선명도를 기록합니다. `image`는 영상별 결과 폴더 기준 `evidence/source-contact-000.jpg` 형식의 5프레임 근거 이미지입니다. `complete`는 시계열을 확보했다는 뜻이며 최초 접촉을 확인했다는 뜻이 아닙니다. 끝부분이 잘렸거나 타임스탬프 간격이 불연속이면 `incomplete`입니다.

```json
{
  "events": {
    "source_contact_patch_size": 96,
    "source_contact_max_candidates": 6,
    "source_contact_model_path": "models/native-contact.pt"
  }
}
```

모델이 없을 때는 `source_contact_model_path`를 생략합니다. 근거 이미지는 생성하지만 `contact_observed`를 변경하지 않습니다. 설정값은 원본 픽셀 기준이며 패치 크기는 24~256의 짝수, 후보 제한은 0~64입니다. 원본 모델의 입력 패치 크기는 학습 체크포인트를 따르므로 근거 이미지 크기와 별개입니다.

## 원본 모델 학습 계약

`train_contact_model(..., preprocessing=SOURCE_PREPROCESSING)` 또는 CLI의 `train-contact --source-resolution`으로 원본 패치 학습을 선택합니다. 입력 라벨의 `analysis_size`, `x`, `y`, `contact_px`는 기존과 동일한 분석 영상 좌표입니다. 추출기가 실제 원본 크기를 확인하고 후보점과 정답 코르크 접촉점을 원본 좌표로 변환합니다. 원본 프레임은 축소하지 않으며 RGB 변환과 화면 밖 검은색 패딩만 적용합니다.

체크포인트에는 `opencv_source_native_bgr_v1` 전처리, 원본 크기, 프레임 간격 범위와 원본 픽셀 기준 위치 오차가 저장됩니다. 추론에서도 같은 패치 함수를 사용합니다. 결과를 판정 엔진에 넘길 때 접촉점은 분석 좌표로 변환하고, 반경·불확실성은 두 축 중 보수적인 배율로 환산합니다.

기존 `opencv_source_bgr_area_v1` 모델은 `events.contact_model_path`에서 계속 사용합니다. 이를 원본 모델 경로에 넣으면 오류를 기록하고 접촉을 확정하지 않습니다. 두 모델 경로는 동시에 설정할 수 없으며, 접촉 위치와 이를 뒷받침한 모델 출처가 서로 섞이지 않도록 분석 전에 오류를 반환합니다. 원본·축소 학습 영역을 섞거나 기존 체크포인트를 자동 승격하지 않습니다.

## 접촉 확정과 검증 범위

기존 독립 랠리 그룹, 확인된 라벨 출처, 홀드아웃 정밀도·위치 오차, 촬영 크기·프레임 간격 검사를 그대로 적용합니다. 관측 가능한 코르크 접촉점의 검수 라벨이 필요하며, 정지·반사광·후보 궤적을 정답으로 만들지 않습니다. 학습이 실행되더라도 이 조건이 충족되지 않으면 모델은 위치 제안만 제공합니다.

접촉 모델의 출력은 대상 셔틀콕 식별 점수나 코트 보정 신뢰도를 올리지 않습니다. 자동 IN/OUT은 세 조건을 각각 통과해야 합니다. 원본 접촉 패치의 생성 성공, 합성 테스트, 모델 제안은 실제 경기 판정 정확도의 측정값이 아닙니다.
